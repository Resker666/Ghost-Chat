# 开源维护

当前维护对象为默认分支中的实验性双人在线文字聊天原型。没有稳定支持版本、服务可用性承诺或长期身份/历史数据兼容承诺；每次实验发布在 CHANGELOG 标明范围。

## 问题分流

公开 bug 表单用于不涉及安全漏洞的复现步骤、版本与界面现象；feature 表单用于使用场景和期望行为。两者不索取个人联系信息、完整 URL、聊天正文、roomId、token、roomSecret、原始日志或抓包，也不要求会话截图。

疑似授权绕过、秘密泄漏、未授权入房、加密/重放问题先按 [SECURITY.md](../SECURITY.md) 私密报告。私密报告功能是否可用以经实际确认的安全政策为准，添加本地模板不会启用平台设置。

模板与勾选项只是提交提醒，不能自动识别或消除所有秘密。误发敏感内容时避免引用、复制或转贴，按平台能力隐藏/移除并私密协调；不能保证互联网副本撤回。活跃邀请泄漏时，持有者应结束受影响会话并重新建立新会话。

## 范围与维护流程

1. 确认是既有承诺缺陷、部署/兼容问题还是产品变更，使用测试专用材料复现。
2. 既有行为按 PRD 与 ADR 检查；断线重连、历史、群聊和文件需要先讨论，P2/P3 不随维护自动实施。
3. 用最小修改配相应测试，保留安全失败策略、同源资源、一次性令牌和不持久化边界。
4. 按提交归档真实命令、CI、环境与结果；不重复标记没有重新执行的检查。
5. 更新设备支持矩阵、CHANGELOG 和限制，再按实验版清单准备发布。

依赖升级保留 lockfile 与许可证，检查可用的依赖/漏洞扫描并运行相关回归。扫描成功不表示独立安全审计，破坏协议的升级先写 ADR 和互通测试。

## 模板维护

模板位于 `.github/ISSUE_TEMPLATE/`，使用 GitHub issue forms 与 contact links。语法参考 [GitHub issue forms](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms) 与 [模板选择器](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/configuring-issue-templates-for-your-repository)。变更先检查 YAML/字段，再在进入默认分支后确认平台实际渲染，不为验证而发布含秘密的问题单。
