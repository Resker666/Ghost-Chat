## 二维码加入后定向回归

2026-10-15，仍在基于 `5a63896` 的未提交工作区，Chromium、Firefox、WebKit、mobile-chromium 和 mobile-webkit 五项目各执行 4 个 QR 用例与 1 个基本双人聊天用例，合计 **25 PASS / 47.8 秒**，输出位于忽略的 `.tools/qr-e2e-results`。web 单元测试另为 **86 PASS / 4 files**。

QR 回归独立解码真实 canvas 像素、在内存核对完整邀请，验证默认隐藏/显式展示与同源请求、隐藏/销毁后 buffer 清空、入场后清理和延迟模块不能重绘已结束邀请。基本聊天同时重跑。

这一组是新增功能的定向回归，与二维码前 115 PASS / 5 SKIP 完整矩阵分开记录，不将两组相加当作 QR 后全量矩阵。未执行真实手机相机扫码，设备模拟和 jsQR 解码均不替代实机。

## 失败输出隐私修复后定向回归

禁自动页面快照、敏感断言布尔化及邀请导航 call log 防护之后，五项目又定向运行基本双人、复制失败显式显示、结束清理复制错误、QR 像素解码、原生进程重启，**25 PASS / 42.8 秒**。输出位于 `.tools/privacy-regression-results`，仍是源码测试与设备模拟，不是实际移动设备。

真实 Playwright 故意失败探针已执行到随机 marker 填入后固定失败，再检查 stdout/stderr 和全部结果文件无 marker/页面快照/媒体。独立安全 reporter 集成也按预期报告一次失败和两个关键用例均未通过；这些是失败路径验证，不计入设备或正向功能通过数。

三组矩阵/定向结果存在重叠且绑定不同阶段的未提交工作区，不能相加。这是容器成功之前的历史阶段，后续正式域名、代码 CI 容器与用户反馈分别见下节；手机相机扫码仍未单独确认。

## 正式域名原生 HTTPS 验证

2026-10-15，Ubuntu 原生 Go + systemd + Nginx 的 [chat.resker666.cloud](https://chat.resker666.cloud) 使用正式 Let's Encrypt 证书，在 Chromium、Firefox、WebKit 和两个移动模拟项目中各执行基本双人、安全头/CSP、本地 QR 解码三例，**15 PASS / 1.9 分钟**。TLS 校验保持开启，实际传输为 WSS，涵盖 Unicode、销毁与无存储检查。

这验证了真实 HTTPS 目标的选定流程；未对正式服务运行短 TTL、重启或负载，未将原生结果计为 Docker TLS 栈通过。该自动化验收阶段尚无用户实机反馈，历史状态保留，最新反馈见下节。临时通道下的续期/hook dry-run 通过后通道已关闭，普通直连仍超时，长期自动续期未通过；这与浏览器会话和当前正式证书有效分开记录。

## 用户实机核心反馈

2026-10-15，用户反馈 Android 与 iPhone 均完成“电脑与手机：扫码或复制邀请→加入→互聊→销毁”，两平台记为 **用户反馈实机核心流程 PASS（2026-10-15）**。该反馈独立于自动化统计，不等于代理现场观察。

未提供设备型号、系统/浏览器名称或版本、网络类型；“扫码或复制邀请”没有指定具体分支，因此相机扫码不能单独标通过。后台/锁屏、网络切换、IME 边界和横竖屏专项仍未验收。

## 最终代码 CI 容器验收

`fa3e721` 的 [CI 8 作业全部通过](https://github.com/Resker666/Ghost-Chat/actions/runs/38706441313)，包含五项目源码 E2E 与实际 Linux 生产镜像 + Nginx 临时测试 CA 的 HTTPS/WSS 验收。容器 runner 默认 Chromium，链/hostname 校验、不可信签发者/错误 hostname 拒绝、加密会话和隔离容器重启均通过。

容器临时 CA 与上述原生正式域名是不同模式，不能因某一模式通过扩大另一模式的设备或续期结论；Android/iPhone 仍仅有已注明的用户核心反馈，专项与 PVR 状态不变。

## 真实设备操作

1. 选择测试专用会话和虚构内容，确认实际 HTTPS 服务被设备信任；不把邀请或聊天上传到问题单。
2. 记录提交/镜像短标识、日期、设备通用型号、OS 与浏览器版本、Wi-Fi/移动网络类型，不记录 IP、序列号或设备唯一 ID。
3. 创建、复制邀请、显式加入和双向发送；包含中文、英文、Emoji、空格、换行和 2 KiB 字节边界。另测本地二维码显式展示/隐藏与真实相机扫码，不上传二维码截图或解码后的邀请。
4. 使用真实软键盘与中文输入法，检查发送、换行、焦点、输入区域、最新消息滚动、横竖屏和放大文字。复制失败时检查界面反馈，不为绕过权限上传秘密。
5. 测试主动销毁、刷新、离线、后台/锁屏和网络切换。被检测到断线就结束且清空，不自动重连；这属于既定产品行为。
6. 测试等待/总 TTL、旧邀请失效及无聊天持久化。只保存无敏感内容的检查摘要，不上传真实截图、原始日志或抓包。

## 记录格式

维护者仅在获得实际证据后把“未测”改为通过或失败，并绑定版本与日期。失败描述使用界面状态和固定错误码，复现内容用测试占位说明；不要附完整 URL、roomId、token 或 roomSecret。

测试 CA、忽略证书错误、自动化移动 viewport 和真机分别记录。增加断线恢复、历史保存或后台保活承诺需要单独产品决策，不以移动兼容修复名义改变 [PRD](PRD.md) 的删除语义。
