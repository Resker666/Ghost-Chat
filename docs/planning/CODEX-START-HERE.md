# Codex 启动说明：Ghost Chat

请先读取同目录下的 `GhostChat-项目总体规划与Codex实施方案.md`，将其视为完整的产品、安全和工程约束。**不要跳过其中的“给 Codex 的执行原则”“威胁模型”和“协议草案”。**

第一轮只实现 **P0 和 P1**：Go + WebSocket 内存房间、React + TypeScript 浏览器客户端、本地 E2EE、一次性邀请链接、双人在线聊天、销毁后不可恢复（应用层）。**P2/P3 是后续设计研究任务，不要假装首版具有 Tor 匿名性、前向保密或强制阻止对方截图等特性。**

## 请立即执行

1. 先检查当前目录和构建环境，写出简短任务计划及确定的协议边界。若没有 git 仓库，则新建 `ghost-chat` 项目目录；不要覆盖用户现有文件。
2. 初始化 `web/`、`server/`、`docs/`、`e2e/`、`deploy/`，落地安全边界文档、协议 schema 和 CI 测试。
3. 实现房间和独立鉴权令牌机制、端到端浏览器加密、WebSocket 中继以及会话生命周期；服务端禁止记录明文或 `roomSecret`。
4. 完成核心 UI，运行真实单元测试和两个浏览器 context 的端到端测试。
5. 修复测试问题，并更新 `docs/PROGRESS.md`：实现项、实际运行命令、通过/失败结果、风险和后续 P1.5 任务。

**请逐阶段落地代码并验证，而不是只输出开发方案。**

## 完成标准

- 双人在线文字聊天正常，网络消息全是加密 envelope。
- 第三人、无效令牌、过期房间被拒绝。
- 任一方手动结束会话后双方退出，服务器释放房间内存状态。
- 页面刷新不可恢复历史；浏览器无聊天持久化。
- 首版明确暴露安全边界：不是绝对匿名，不保证密钥内存物理擦除，不具有前向保密。
- README 能指导一台开发机从零启动并完成测试。
