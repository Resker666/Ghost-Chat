# 产品范围与验收边界

日期：2026-10-14。原始完整规划与启动说明归档于 [planning/](planning/README.md)。当前实施约束以本文、架构、协议、威胁模型及 ADR 为准；原文中的冲突按已确认决策解释，历史任务指令不要求重新初始化项目。

## 本轮交付

无账号、双人、仅在线文字聊天。React + TypeScript 客户端本地生成秘密并加密，Go 单进程仅保存内存房间并中继密文。没有数据库、Redis、离线队列、历史查询、图片、文件、音视频或群聊。

顺序为 P0 工程骨架及决策并验证，P1 可运行 E2EE 聊天及真实浏览器验收并记录，随后 P1.5 安全加固与可部署。P2/P3 不实现，也不宣称前向保密、Tor 或抵御恶意 Web 发布者。

## 已确认的产品决策

- 任一已鉴权参与者断线即结束整个房间，双方清空，令牌不复用，不重连。
- 新建房间在首次成功鉴权前允许没有在线用户；创建后 10 分钟内双方未全部到齐即过期。
- 总 TTL 从房间创建算起，默认 30 分钟；配置和测试可以缩短。
- B 解析并立即移除 URL fragment 后，显式点击加入才消费一次性令牌。
- 开源许可证采用 MIT。

## 核心体验

1. A 创建房间，本地生成 256 位 `roomSecret`，取得服务端独立的 A/B 访问令牌。
2. A 分享包含 B 令牌及 `roomSecret` 的邀请 fragment；B 先清理地址栏，再主动加入。
3. 双方在线并收到 ready 后才能发送；每条明文最多 2 KiB UTF-8。
4. 展示等待、已连接、网络断开、销毁/到期状态和服务器到期时间。
5. 任一端销毁、断线或到期后关闭连接，清空页面状态，原链接失效。

邀请只证明持有该链接，不能确认真实世界身份。复制链接、页面刷新、断线删除和截图风险须在相应界面明示。

## 完成定义

两独立 Chromium contexts 真正互聊；网络中的聊天是加密 envelope；错误令牌、第三人、令牌重用、篡改及重放被拒；销毁、断线、到期、刷新后不能恢复；浏览器无聊天持久化；运行命令及实际结果可复现。
