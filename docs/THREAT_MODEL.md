# 威胁模型

Ghost Chat 是实验性 E2EE 原型，目标是减少账号和聊天历史带来的暴露。未经过独立安全审计，不适合高风险保密。

## 保护对象与假设

保护聊天正文与本地 `roomSecret` 不进入正常实现的中继；限制房间为两个一次性角色；结束后不提供应用层历史恢复。

必须信任浏览器所执行的客户端代码与终端。生产部署必须使用 HTTPS/WSS，所有应用资源同源自托管。完整邀请链接是秘密，带外分享渠道也是信任边界。

| 攻击者 | 首版目标 | 剩余风险 |
| --- | --- | --- |
| 网络旁观者 | TLS + 客户端加密保护正文 | 时序、长度、目标及流量关联仍存在 |
| 被动中继运营者 | 不接触明文与 roomSecret | 能看到 IP、角色、roomId 和元数据 |
| 恶意 Web 发布者 | 锁依赖、CSP、开源审阅降低风险 | 能替换 JS 窃取密钥与明文 |
| 获得邀请链接的人 | 最多两角色、令牌一次性 | 可以抢先加入或冒充接收者 |
| 恶意参与者 | 不提供服务端历史 | 能截图、复制、录屏或保留秘密 |
| XSS / 扩展 / 被攻破终端 | 安全文本渲染、无远程第三方脚本、CSP | 终端攻击能读取页面与内存 |
| 资源滥用者 | 帧/队列/房间/连接与速率上限 | 单实例不能承诺抗大规模拒绝服务 |

## 协议边界

角色令牌与加密秘密独立。A/B 各自一次性；令牌不是加密密钥，不进入 URL query。方向密钥不同，AAD 绑定版本、房间、方向、序号；接收端拒绝重放和无效输入。

首版共享秘密方案没有前向保密。保留邀请链接或秘密的人可能事后解密录制密文。没有持久身份、安全码或可信联系人，持有邀请不等于确认真实身份。

## 删除语义

- 服务端：移除房间、关闭连接、清空有界队列并释放引用。不能保证分配器、交换区、转储或基础设施副本已物理擦除。
- 浏览器：清空消息、React 状态、可覆盖字节数组及密钥引用。JS 不可变字符串、GC、浏览器内部副本与系统交换区不能保证即时擦除。
- 对方设备：不能远程删除保存的内容，也不能阻止截图、复制、扩展或录屏。
- 历史：刷新、断线、销毁、到期或进程重启后无系统恢复功能；这不等于法证级不可恢复。

## 禁止宣称

不得宣称绝对匿名、无法追踪、运营者无论如何都看不到内容、物理彻底擦除、阻止截图、Signal/Double Ratchet 前向保密或已通过独立安全审计。

## 发布边界

P1 的本地闭环不代表生产部署完成。P1.5 需审查应用/代理/云日志、TLS、安全头、容量、进程权限和诊断配置。公开使用前安排独立审查。
