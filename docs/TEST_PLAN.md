# 测试计划

本文件定义验收，实际执行命令与结果见 [PROGRESS.md](PROGRESS.md)。所有测试使用固定或随机的测试专用秘密与虚构文字；真实用户数据不得进入截图、trace 或 CI artifact。

## 分阶段门槛

| 阶段 | 必要证据 |
| --- | --- |
| P0 | 前端 lint/typecheck/unit/build；Go healthcheck 与单元测试；架构/威胁/协议/CI 已建立 |
| P1 | 真 Chromium 两独立 contexts 的创建、加入、双向加密互聊及失败场景；单元和协议边界通过；记录实际结果 |
| P1.5 | Go race/vet；慢连接/并发/资源/重启回归；安全头/Origin/日志审查；部署运行证据或明确未执行 |

P1 核心授权、schema、帧上限、超时与基本资源边界仍需测试；它们不是可推迟的 P1.5 功能。

## 自动化矩阵

| 范围 | 检查 | 预期 |
| --- | --- | --- |
| 加密 | 中文、英文、Emoji、空格与空白边界 | 原样还原，服务端接收的是 ciphertext envelope |
| 加密失败 | 错 secret、篡改 ciphertext/IV/AAD/seq | 不展示消息，不推进已接受序号 |
| 密钥/IV | 相同上下文可互通、方向密钥分离、IV 碰撞/计数上限 | 用途不混淆、IV 不复用、上限后拒绝 |
| 重放 | 重复/过旧 seq | 拒绝，不显示重复明文 |
| 授权 | 错 token、A/B token 复用、第三客户端、鉴权超时 | 拒绝；未鉴权者不能销毁正常房间 |
| 生命周期 | 未鉴权零人、双方未到齐超时、总 TTL | 创建不立即失效；期限到达后关闭并清理 |
| 结束 | A/B destroy、任一断线/刷新、重复 close | 双方清空并结束，原邀请/令牌无法恢复 |
| 重启 | 服务端重启 | 旧房间失效，无历史恢复 |
| 大小/格式 | UTF-8 2,048 字节边界、超长帧、畸形 JSON/base64url、未知字段/版本 | 安全拒绝，无 panic、阻塞或无限内存 |
| 浏览器 | XSS 文本、fragment 清理、无外部请求、无持久化存储 | 文本渲染；秘密不进入请求或存储 |
| 本地二维码 | 独立 jsQR 解码实际 canvas；默认隐藏、显式开关、就绪/结束清理、晚到绘制 | 仅在内存核对完整邀请，不输出或截图；所有请求保持同源；真机相机单独验证 |
| Origin | 缺失/错误/允许 Origin | 按明确策略拒绝或放行，不能代替 token 认证 |
| 并发 | 多房间、竞态销毁、慢读/写、取消、容量 | 有界资源、无 goroutine 泄漏或 race |
| 隐私 | HTTP/WS、日志、代理、浏览器与测试 artifacts | 无明文聊天/roomSecret 上行，无敏感日志 |
| 体验 | 桌面/移动 viewport、键盘焦点、复制与发送状态 | 流程可操作，无文本重叠/截断 |

## 证据方法

双 context 必须运行真实浏览器与 Web Crypto，不用 mock 替代。通过测试专用 HTTP/WebSocket 观察点校验发送边界，区分 auth/control 元数据和加密聊天。“日志无明文”不能单独证明 E2EE。

测试隐私必须覆盖失败路径：禁用自动页面快照以及 trace/视频/截图，敏感 locator 与解码值改为仅报告布尔结论，避免错误正文含完整邀请。`error-context.md` 等固定诊断文件可以存在，不能将“没有所有错误文件”当成目标；真正检查项是其内容和 stdout/stderr 不含秘密、页面快照或可见 QR。故意失败探针按预期 exit 1，再由父检查确认无泄漏，独立记录为负向验证，不计入正常功能通过数。

隔离容器 runner 还需检查实际结果：基础聊天和容器重启必须均通过，排除仅列用例、全跳过或过滤关键用例造成的假成功；不允许自定义 `--reporter` 绕过安全统计。计数/关键用例布尔结论与 Docker JSON/stdout、基础设施 stderr 分流，不直接拼接原始错误正文到验收报告。

TTL 单测注入时钟或使用缩短的测试配置，生产默认值仍明确为创建后 10/30 分钟。记录运行系统、工具版本、命令、退出码与测试数量。

首次 Chromium 通过仅代表该实测范围；Firefox/WebKit、移动设备、TLS 生产环境和 Docker 必须单独验证后才能称兼容或可部署。

## 部署与设备证据分层

| 模式 | 已知范围或待验证出口 |
| --- | --- |
| Windows 原生 Go + Chrome | 2026-10-14 的 14 个 E2E 和本机试用已记录 |
| Linux CI 原生 Go + Chromium | 提交 `v1-baseline` 的 run 38558565586 四作业成功，完整证据见开发记录 |
| Linux 生产镜像基础运行 | 同一 CI 已通过 Docker build、Compose config、只读非 root health/static smoke |
| 生产镜像完整聊天 | 待验证互聊、令牌/错误输入、销毁、断线、过期及重启；不得用基础 smoke 替代 |
| Ubuntu 原生 systemd + Nginx 正式 HTTPS/WSS | 已实际通过正式域名五项目选定三例/项目，共 15；TLS/WSS、Unicode/销毁/无存储、安全头/CSP、QR；没有生产 TTL/重启/负载或真机结论 |
| 容器 Nginx + HTTPS/WSS | 仍待实际执行完整 runner；原生正式域名成功不代替容器测试，测试 CA/忽略证书错误必须明确标注 |
| 真实设备/不同网络 | 2026-10-15 用户反馈 Android/iPhone 的电脑↔手机核心流程 PASS；非代理独立观测，OS/浏览器/网络和扫码或复制分支未提供，专项未验收 |

每份证据绑定具体提交、镜像、浏览器版本、日期与命令。后续提交不能仅引用旧提交通过来宣称自身已验收。[设备支持矩阵](DEVICE_SUPPORT.md) 记录待测与实际支持范围；[实验版清单](RELEASE_CHECKLIST.md) 约束发布表述。

新增入口与边界依据 [ADR 0005](decisions/0005-mobile-and-browser-validation.md)：Chromium 默认入口和五项目矩阵分开；外部 origin 跳过原生进程重启；短 TTL 仅在专用测试实例明确启用；容器重启限于 runner 创建的随机项目。正式服务只跑指定基础用例，不修改其 TTL/limits。命令与变量见 [部署测试接口](DEPLOYMENT.md#测试入口与目标范围)。

焦点循环、390×320 小高度视口和 IME Enter 回归先记录失败证据，再记录具体修复与重测结果。合成 composition/keyCode 事件不能替代真实输入法，虚拟键盘/viewport 模拟也不能替代真机软键盘。浏览器被沙箱阻止启动属于环境结果；需在可运行环境复测后再评价应用兼容性。

## 环境限制

2026-10-14 Windows 本机为 Node.js 24.11.1 / npm 11.6.2、便携 Go 1.27.2，未安装 Docker；此为历史环境。2026-10-15 已核实远程 Linux CI 与容器基础检查成功，不能外推至未测试设备或完整生产部署。本地/远程结果在开发记录分别登记。
